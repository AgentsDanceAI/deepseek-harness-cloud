# DSH Cloud 0.2.1

自部署第一次运行的体验修复版。上一版装完之后，用户会撞上一连串没人领路的墙——
这一版把它们逐个拆掉，全部来自真实安装过程中的实测。

## 新增功能

- feat(cli): 首次运行引导——`start` 会问三件事（OpenAI 兼容端点、它的 API Key、
  可选的搜索 Key），写好 `.env`、拉起整栈、打印登录指引。密钥只从 TTY 读且不回显，
  绝不经命令行参数；非交互环境（CI / `--json` / `--yes` / 无 TTY）一个字都不问，
  行为与之前逐字节相同
- feat(cli): 自部署引导补上登录配置（SMTP 或 GitHub/Google OAuth）——没有它谁也
  注册不了第一个账号，而 `start` 本来就会硬拒
- feat(cli): 自部署默认开云工作台——`WORK_ENABLED` / `WORK_DOMAIN` /
  `COOKIE_DOMAIN` / `COMPOSE_PROFILES` 此前一个都没写进 `.env`，于是自部署必然
  拿不到这个招牌功能。现在有域名就默认全开，面板并点名那条还差的 DNS 记录
- feat(cli): 搜索配置位（`SEARCH_PROVIDER` / `ZHIPU_SEARCH_API_KEY`）进 `.env`
  模板——此前这个能力只活在源码里，要读代码才知道可以接自己的搜索
- feat(web): 本部署给不了的能力挂出官方托管版入口，明确标注是托管版；自部署方
  置空 `HOSTED_SITE` 即可整条关掉

## 优化改进

- README 的"从源码"两段压成两行命令，单容器改用预构建镜像；模型目录（20 个 /
  11 家）上首页，并由合同测试与 `models.json` 双向互钉
- 引导收尾附一句 star 邀请（给链接，绝不代点）
- 面板里的命令改为与工作目录、与 PATH 都无关：取码用 `docker logs`，`up`/`down`
  显式带 `--dir`，并按实际调用方式（`npx` / `uvx` / 源码）印出真能跑的那一条
- 登录那行按模式说实话：自部署配了 SMTP 就是真发邮件，不再让人去日志里捞
- `packages/cli-npm` 的测试接入 CI——这套一直存在却从没被跑过

## Bug 修复

- fix(web): 自部署点"云端体验"进死循环——`/work` 在工作台关闭时 302 到
  `/download`，而下载页写着"安装包正在重新构建，这段时间可以直接用浏览器版
  云工作台"并指回 `/work`。两句对自部署都不成立。工作台关闭时改为不渲染相关入口
  并说明实情
- fix(web): 首页那个"今天要交给 AI 做什么"的输入框仍硬指着本站 `/work`——它是
  首页最显眼的元素，工作台关闭时回车即落进死胡同
- fix(login): 开发模式下验证码只打到服务端日志，而登录页只字未提，自部署用户
  首次登录必卡且无线索
- fix(cli): stdin 中途关闭（Ctrl-D 或 `start < /dev/null`）时取默认值继续，
  不再永久挂在问号后面
- fix(cli): 两个安装器的 `.env` 键序对齐，现由逐字节 parity 用例钉死
