# 自部署安全指南

[English](security.md) | 简体中文

本文补充 [安全报告政策](../SECURITY.zh-CN.md)，是部署清单，不是认证或保证。
自部署方负责威胁模型、基础设施、提供方、备份、监控和事件响应。

## 暴露公网前

- 使用持续接收安全更新的独立主机或账号；
- 生成唯一高熵 `AUTH_SECRET`，必要时使用受保护的 `AUTH_SECRET_FILE`；
- 把上游、OAuth、SMTP、数据库和支付凭证放在 Git 与镜像之外；
- 在 HTTPS 反向代理后运行应用，不直接暴露 `8100`；
- 精确配置公开 Origin 和 OAuth 回调，公网关闭 `DHC_DEV`；
- 关闭未使用的登录、支付、搜索、工作区和提供方集成；
- 使用专用数据库账号、加密备份和脱敏日志。

## 探针与请求边界

`/livez` 仅用于进程存活，`/readyz` 用于流量就绪，`/api/health` 只是兼容性存活端点。
默认普通 API 请求体上限 2 MiB，支付 webhook 256 KiB；网关和反向代理应设置相同或
更严格的连接、头部、请求体、上游和空闲超时。

HTML 响应带 CSP，HTTPS 带 HSTS。必须检查最终公网响应，不能假设 CDN/代理保留了
应用头部。

## 身份、网关和预览

轮换 `AUTH_SECRET` 会使现有会话和设备退出，应有计划执行。泄露凭证必须先在提供方
吊销。不要把通用账号或上游令牌注入可执行用户代码的工作区。

模型网关只允许已配置的上游和模型，使用 TLS、超时、有界响应和最小权限凭证。
预览内容应使用独立 Origin；非 HTML 流式转发，HTML 重写受
`PREVIEW_HTML_MAX_BYTES`（默认 8 MiB）限制。

## 支付、数据与工作区

启用支付时必须验证 webhook、幂等处理事件，并在服务端裁定商品、金额、币种、用户
和权益。测试退款与拒付，不在公开报告中附原始支付载荷。

数据库、上传、日志、备份和支持材料都可能包含个人数据。记录目的、保留期、访问者
和删除流程，并定期执行恢复测试。

工作区会执行用户代码，容器和 Docker socket proxy 不构成恶意多租户的完整安全
边界。启用前审查镜像、权限、网络、挂载、出网、凭证、资源限制和跨租户隔离。
