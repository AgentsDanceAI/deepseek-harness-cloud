# 每人一台云电脑 (personal box) — 形态设计

老板 2026-09-07 定的方向: DSH 从**「点一格开一个应用」**改成**「每人一台装了全套 AI
的电脑」**。他的原话比喻是「Box 像移动 U 盘, 谁用给谁插上, 里面有全套 AI」。

这不是选型问题, 是产品形态问题:

| | 现在 | 新形态 |
|---|---|---|
| 心智 | 共享办公室的工位 | 我的随身电脑 |
| 单位 | 一个 (用户, 产品) 一个 Pod | 一个用户一台机器 |
| 数据 | 正本在 OSS, 进出同步 | 就住在这台机器上 |
| 隔离 | 我们自己搭的 gVisor | 供应商给的 VM |
| 等待 | 开一格 2 秒 | 开机约 20 秒, 之后开格子是秒级 |

**为什么这个形态能容忍 20 秒而现在的形态不能**: 用户对「我的电脑要开机」有预期,
对「点开一个网页转 20 秒」没有。同一个数字, 换个心智就从故障变成常态。ADC 那条云电脑
就是这么做的 —— 它的卡片把「休眠 · 不计费」当正常态展示。

## 支撑决定的实测 (2026-09-06/07)

全部在真机上量的, 不是估算。方法与原始数字见 `deploy/box-node/README.md`。

| 量 | 值 | 备注 |
|---|---|---|
| 干净盒子冷启动 | **7 / 19 / 24 / 18 秒** (四轮) | 停机→开机→公网 URL 返回 200 |
| 盒子里起一个已装好的容器 | 与开机重叠, 不额外收时间 | 盒内 localhost 与公网路由同秒通 |
| 全部 15 格镜像 | **10.04 GB 压缩** (解开 20–25 GB) | `default` 盘剩 49 GB, **全套装得下** |
| 镜像拉取速度 | 27 MB/s | 5 GB 约 3 分钟 |
| docker 镜像/容器/命名卷 | **跨停机存活** | 虽然在 `/var/lib/docker` (快照文档没列这个目录) |
| `/host` 的公网 URL | **跨停机稳定** | 开机后原样可用 |
| 停机成本 | **0** | 快照留着 |

⚠️ **别拿 API 的 `state` 当就绪信号**: 状态 7–9 秒就报 `ready`, 服务还要再等 10–15 秒。

## 设计决策

每条都是「决定 + 为什么 + 代价」。没有代价的决定通常是没想清楚。

### 1. 镜像预装, 服务按需起

一台盒子里预装全部 15 格的镜像 (10 GB, 装得下), 但**容器不开机自启** —— 用户点哪格
才 `docker start` 哪格。

*为什么*: 镜像躺在盘上不吃内存, 容器跑起来才吃。15 格全自启没有任何档位装得下。

*代价*: 用户开第一格 = 开机(20s) + 起容器; 开第二格 = 只起容器 (单容器产品秒级,
Dify 那种九容器栈 30 秒到两分钟 —— 但那在今天的 Pod 模型下也一样要等)。

### 2. 规格按套餐定, 不动态换

Free/Pro (并发 1–2 格) → `default` 4C/8G; 更高档 (并发 3–4 格) → `large` 8C/16G。

*为什么*: Coze 下架后最重的产品是 4 GB, `default` 能同时跑两格。平台支持 resume 时
换规格, 但换档要停机再开 —— 用户会多等一次 20 秒, 而且发生在他正想干活的时候。
可预期比省钱重要。

*代价*: 高档用户即使只开一格轻产品也按 `large` 计费 (2×)。以后按「当前要开的格子」
动态选档是优化项, 不是第一版。

### 3. 文件: 放 `/home/user` 下, 每产品一个目录, 外加一个显式共享目录

```
/home/user/dsh/<product>/home        取代今天的 <hexid>/home
/home/user/dsh/<product>/workspace   取代今天的 <hexid>/workspace
/home/user/dsh/shared                新增 —— 所有格子都挂到同一个 /shared
```

⚠️ **路径不能随便挑, `/data` 不进快照。** 2026-09-07 实测, 同一台盒子同时写三个位置
再停机, 然后从快照里取:

| 写在哪 | 快照里 | 取回 |
|---|---|---|
| `/data/p1/workspace/hello.txt` | 没有 | `404 path_not_found` |
| `/opt/dsh/p1/workspace/hello.txt` | `__system__/opt/dsh/...` | ✅ 内容正确 |
| `/home/user/hello.txt` | `hello.txt` (相对 home) | ✅ 内容正确 |

选 `/home/user` 而不是 `/opt`: 它是盒子天然的用户目录, 快照树里的路径就是相对它的
(`/opt` 会被归到 `__system__/` 下, 那是"系统改动"那一档, 语义不对)。

*为什么不干脆全合并成一个工作区*: 不同产品对 `$HOME` 的期待不同, 配置文件会互相打架;
而且共享工作区会让上一次的产物污染下一次 (我们在智能体那条线上栽过, 全程不报错)。

*为什么要有 `shared`*: 这是「U 盘」这个比喻最值钱的部分 —— 在 Claude Code 里生成的
文件能直接在 ComfyUI 里用。显式的一个共享目录既拿到好处, 又不让配置互相污染。

*代价*: 用户要理解「这个格子自己的文件」和「共享的文件」两个概念, UI 上得说清楚。
另: 各产品容器的 uid 不一 (root / 1000 / 1001), 挂载时属主要一次性对好 —— 属主不对
是「起来了但写不进去」, 不报错 (今天在 k8s 的 subPath 上栽过一次)。

### 4. 冷启动照实说, 不假装

抄 ADC 的做法: 休眠是**正常态**不是故障。

- 卡片常态显示「休眠 · 不计费」, 而不是灰掉或报错
- 点开时给分段进度 (开机 → 起服务 → 就绪), 不是无差别转圈
- **就绪判据用产品自己的 `ready_path`**, 不用 Box 的 `state` (见上面那条警告)

### 5. 镜像升级: 底片定期重建 + 已有盒子拉增量

平台**没有**把新镜像推到已有盒子的接口 —— 实测 `environments/upgrade` 只推 env 变量
和 secret 文件 (而且对运行中的盒子, API 返回成功但盒内的值没变, 要停机再开才生效);
命名快照 (底片) 只在**新建**盒子时用, 没有接口能把新底片贴回一台已有的盒子。

所以升级靠 docker 本来的分层增量:

- **底片定期重建** → 新用户开箱即新
- **已有盒子**在开某格时按需 `docker pull`, 只拉变化的层

*前提*: 我们的镜像分层必须干净。2026-09-07 之前不干净 —— `ARG REVISION` 声明在
`FROM` 下一行, 每次构建都让后面所有重活层失效 (agentui 每版重下 326 MB/81%,
comfy-local 95.8%)。已修 (`ARG` 和 `LABEL` 挪到文件末尾), A/B 实测第二遍构建
CACHED 层 3→12、70 秒→0 秒。**这条修好之前, 整个形态不成立** —— 每次改版每个用户
重拉整包是不可接受的。

### 6. 数据的家, 和一条导出路径

盒子的快照就是用户数据的家。快照绑在盒子上, 所以必须有一条**不开机也能取回文件**的
路径 —— **已验通** (2026-09-07):

```
GET /boxes/{id}/snapshots/latest     → 拿到 snapshot id
GET /snapshots/{id}/tree             → 平铺的文件清单, 带大小
GET /snapshots/{id}/files?path=<绝对路径>   → 文件字节 (目录则是 tar)
```

盒子处于 `archived` 状态时全程可用, 不用开机、不花机时。所以「用户下载自己的产物」和
「注销时导出」都成立, **不需要把 OSS 同步请回来** —— 这是这个形态最主要的减法能保住的
前提。

*已知边界*: 基础镜像自带的文件取不到 (`base_image_file`), 符号链接要取它的目标
(`is_symlink`), 太老的快照格式没有索引 (`snapshot_not_indexed`)。这三条对用户自己
产生的文件都不构成问题。

## 路由: 不走 `/host` 的公网 URL, 每台盒子拉一条 WireGuard

这一条原本被列为最大风险。2026-09-07 实测之后有了答案, 而且是现成的。

**`/host` 那条路走不通。** 它给的 URL 带查询参数里的令牌, 实测:

| 传法 | 结果 |
|---|---|
| `?_token=<tok>` | **302** (不是 200 —— 是重定向, 边缘想给浏览器种 cookie) |
| 什么都不带 | 403 |
| `Authorization: Bearer` | 403 |
| `Cookie: _token=` | 403 |
| `X-Ascii-Token` 头 | 403 |

令牌**只认查询参数**, 而且是**面向浏览器的重定向流程**, 不是面向反代的。用 Caddy 反代
它, 那个 302 会被透传给浏览器, 浏览器就跳到 `*.on.ascii.dev` 去了 —— **人当场离开我们
的域名**, 我们的会话注入和 nginx 伴随容器全部失效。
另一条 `public: true` 能拿到干净的 HTTPS 上游, 但那等于谁拿到 URL 谁进得去, 而我们的
产品一律不留第二道登录墙, 没有第二重防线。

**改用: 每台盒子出站拉一条 WireGuard 到应用机。** 盒子拿一个隧道地址, Caddy 反代
`<隧道IP>:<端口>` —— **和今天的 `X-Work-Upstream: <host>:<port>` 契约一模一样**,
上游那一层一行都不用改。

这条不是设想, 是**已经建成并验过的东西**: 备用节点就是这么连的 (`deploy/box-node/`,
`tunnel-wg-144.sh`)。当时选它的理由在这里同样成立 —— 盒子每次 resume 都可能换机器、
换地址、甚至只有 IPv6, 而 WireGuard 的对端不写 Endpoint, 由盒子出站拨过来, **地址怎么
变都只认公钥**。

要补的只有「一台」到「N 台」:

- 应用机上从一个对端变成一个对端池, 每台盒子一个 `/32` (从一个 /16 里分)
- 建盒子时生成密钥并登记对端 (备用节点那条流程照搬)
- 应用机侧的围栏按对端收紧: 只放行「应用机主动发起之后的回程包」, 盒子主动碰不到应用机
  (工作台 Pod 调网关走公网, 现在的 netpol 已经把整个 10/8 排除在出站白名单外)

*代价*: 应用机成了 N 个盒子的 WireGuard 枢纽。WireGuard 本身撑得住成千对端, 但这是
一个新的单点 —— 它挂了所有工作台一起不可达。今天的隧道也是同一个形状 (一条隧道挂了
一整个节点没了), 所以不是新增的风险类别, 但规模变了。

## 明确不做的

- **不整体切换。** 现在的 Pod 模型继续跑, 新形态先挑一格双轨。
- **不合并所有产品的文件。** 见决策 3。
- **不为了省钱做动态换档。** 见决策 2。
- **不碰备用节点那条线。** `deploy/box-node/` 是「一台 Box 当一个 k3s 节点」, 目的是
  248 被回收时服务不死, 与本设计无关, 已完工并验过。

## 试点结果 (2026-09-07)

脚本在 `deploy/personal-box/` (`pilot.sh` 端到端建+验, `provision.sh` 在盒子里装机)。
用的是**真实产品镜像和线上真实的启动脚本** —— `boot_script()` / `env_for()` 都从跑着的
dhc-server 里取, 不手写, 所以过了就说明 BoxBackend 照着做即可。

拿 Claude Code (agentui, 单容器, 8080) 走了一遍:

```
1/6 建盒子                   default 4C/8G, 隧道地址 10.99.1.10
2/6 装机                     WireGuard 起并 enable / 目录建好 / 镜像拉好 (盘剩 48G)
3/6 登记对端                 alice → 10.99.1.10/32 (与 standby 共用同一个接口和端口)
4/6 握手                     1 秒
5/6 起产品容器               线上真实 boot 脚本 + env
6/6 反代                     宿主 → 200 · dhc-server 容器里 → 200 · 产品就绪探针 → 200
```

**停机 → 开机, 中间不碰任何东西**:

| | 秒 |
|---|---|
| 页面重新可用 (真实产品, 经隧道, 容器里验的) | **31** |
| 对照: 空盒子只起一个 nginx | 20 |
| 对照: 今天节点上起一个 Pod | 2 |

多出来的约 11 秒是产品自己启动 (agentui 的 boot: chown → 种首跑向导 → uvicorn)。
隧道、容器、对端登记全部自己回来 —— 私钥在 `/opt` 进快照所以公钥不变, 容器
`--restart=always`, 应用机那边的对端一直有效。

**踩到并已修的**: `box run` 是以 `user` 身份跑的, 读 `/opt/dsh-wg/dsh0.pub` (root 0700)
拿到的是**空串**, 一路静默传到 `peer-add` 才报"要公钥"。已加 `sudo` 和一道空值闸 ——
这种"空值静默往下传"的形状比报错难查得多。

### 还没做的 (BoxBackend 那一层)

试点是手工编排的。要变成产品还差:

- `BoxBackend` 实现 `Backend` 抽象 (`inspect` / `create` / `release` / `destroy` /
  `running_users`), `inspect` 返回的 `host` 就是隧道地址 —— 上游契约不用改
- 建盒子时自动分配隧道地址 + 登记对端 (试点里是脚本算的 `10.99.1.N`)
- 闲置停机与计费口径 (Box 按秒计, 规格加权; 与现在按内存折算的 units 要对齐)
- 前端: 休眠态怎么展示、31 秒怎么给进度
