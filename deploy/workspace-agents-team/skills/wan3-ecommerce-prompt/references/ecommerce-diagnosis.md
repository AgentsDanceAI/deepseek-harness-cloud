# 电商 BadCase 诊断手册

**流程**：复述现象（不猜）→ 症状归因 → 最小补丁 → 复测建议。
**四类归因**：`提示词写法` / `形态选错` / `参数不匹配` / `模型能力边界`。
归因到**模型能力边界**必须明说"这不是提示词能解决的"，给替代路径，不要用补丁堆砌假装解决。

## 零、先做一致性体检（占 BadCase 大半）

拿到老 prompt，先扫这八项，命中就直接是补丁：

1. 残留「不要 X / 避免 X / 不出现 X」 → `negative_prompt` 已废弃，改正向排除（`wan3-protocol.md` §4）
2. 用了老写法「图1 / 视频1」 → 改成官方 `@图片1 / @视频1 / @音频1`
3. 声音层为空 → `audio` 默认 true，模型自己编旁白与 BGM，补「全片无台词，无背景音乐，仅保留 XX 音效」
4. 比例写在文字里（"竖屏""9:16 构图"） → 改传参数 `ratio`
5. 分镜没声明 → 不写模型自行切镜，要单镜头就补「生成单镜头」
6. 多镜头时间戳不连续 / 各段之和 ≠ `duration` → 模型自行压缩或拖长分镜，改成首尾相接且求和等于时长（`prompt-craft-discipline.md` §1）
7. 正文自相矛盾（既写「固定镜头」又写「环绕」、既要「logo 全程朝向镜头」又要「360 度环绕」） → 互斥项只能留一个，对照 `prompt-craft-discipline.md` §3 互斥组合表
8. 用了「不得出现 X / 不得拆成 X」这类**否定式存在锁** → wan3.0 对否定存在锁反应过度，会把整个相关镜头或物体**直接删掉**（实测：写「不得出现完整管身」曾导致所有产品镜头凭空消失）。改用**正面计数约束**：「部件共 N 件，不多不少」「只有这一支，只操作一端」。这与第 1 条同源，但 negative_prompt 是参数层，这里是**正文里的否定句**，一样要清。

## 一、症状 → 归因 → 最小补丁

### A. 商品相关

| 症状 | 归因 | 最小补丁 |
|---|---|---|
| 商品外观漂移（颜色/纹理变了） | 形态选错：走了 T2V 或首帧，没走全能参考 | 改 `reference_image` 传商品图；提示词删掉外观复述，只留动作与运镜 |
| 商品外观漂移（已用参考图） | 提示词写法：复述了外观，抢走注意力 | **删**所有"…的釉面/颜色/材质是…"句；**加**「商品轮廓与比例全程保持稳定，表面纹理与颜色保持一致」 |
| 商品中途被晃出画 / 占比变小 | 提示词写法：没写画面占比与朝向锚点 | **加**「商品在画面中占据<中景约三分之一>的稳定位置，正面朝向镜头一侧」；运镜改「固定镜头」或缩小幅度 |
| 商品变形 / 轮廓崩 | 提示词写法 + 能力边界 | **加**「商品轮廓连续完整，边缘清晰，比例稳定」；若是高危物理交互动作 → 见 D 类 |
| 多商品串味（A 的图案跑到 B 上） | 提示词写法：指代不清 | 每个商品都用 `@图片N 的…` 显式指代，并写清各自位置（画面左/中/右）；关键位置**重复 @ 一次** |
| 参考图里同一商品含两个状态（已组装+未组装 / 带盖+开盖 / 正面+背面），成片把两个状态都画进同框、复制成两件 | **参考图问题** + 写法 | 把参考图**裁成只含单一状态**再传（这是根因，比任何提示词都有效）；提示词**加**「画面构图与参考图同构」+ 正面计数「部件共 N 件，不多不少」；**不要**写「不得出现第二件」（否定存在锁，见零节 #8） |
| 指代整个失灵（模型没认参考图） | 提示词写法：用了老写法「图1」或写成"参考图" | 全部改成官方 `@图片1`（带 @、用全称"图片"）；核对 `@图片N` 序号 = 该类型内上传顺序 |

### B. 文字 / logo

| 症状 | 归因 | 最小补丁 |
|---|---|---|
| logo 乱码 / 糊 | 提示词写法：要求模型**生成**文字 | **删**任何"包装上写着 XXX"「印有品牌名 XXX」；改为参考图承载 + 「包装文字保持清晰完整，朝向镜头，无形变」 |
| 文字后期扭曲 | 提示词写法：运镜幅度太大 | 运镜降级为「固定镜头」或「镜头极缓慢推进」；**加**「logo 始终朝向镜头且保持清晰不形变」 |
| 出现莫名字幕/水印 | 提示词写法：没写排除层；或 `watermark` 传了 true | **加**「画面干净无叠加图形，纯实拍质感」；确认 `watermark=false` |

> wan3.0 的文字乱码控制**较稳**，若仍严重，先怀疑是"让模型生成新文字"而不是模型能力。

### C. 声音

| 症状 | 归因 | 最小补丁 |
|---|---|---|
| 凭空出现旁白 / BGM | 提示词写法：没写声音层，`audio` 默认 true | **加**「全片无台词，无背景音乐，仅保留 <XX> 环境音」（官方控制词是「全片无台词」「无背景音乐」） |
| 台词被念错 / 改写 | 提示词写法：台词没用引号内嵌 | 改成 `@图片1 说道："<台词原文>"`，引号内不要加解释 |
| 台词念不完就截断 | 参数不匹配：字数超时长 | 台词压到 ≈ `duration × 4` 字；或 `duration` 加长；或拆两段，第二段首句加衔接锚点 |
| 音色不对 / 每次都变 | 形态选错：没挂 `reference_voice` | 给该角色的 `reference_image`/`reference_video` 挂 `reference_voice`；也可在台词同句内写「…说："<台词>"，音色参考 @音频1」，两者可叠加 |
| 写了音色参考但不生效 | 提示词写法：音色参考没绑在台词句上（如「提取 @音频1 中的音色特征，并让角色说…」前置声明） | **改**成台词同句绑定：「@图片1 用<情绪>的声音说："<台词>"，音色参考 @音频1」；**删**所有"提取音色特征"式前置句 |
| 音效跟画面不同步 | 提示词写法：音效写得太笼统 | 按官方三段写「音源材质 + 行为 + 环境音」，跟着物理衰减走：「每一次弹跳精确同步的敲击声，音量逐次减弱」 |
| 口播语气飘 | 提示词写法：人声六要素缺项 | 补齐 **"内容" + 情绪 + 语调 + 语速 + 音色 + 口音**，缺一项模型自由发挥一项 |

### D. 物理 / 稳定性（wan3.0 已知弱项）

| 症状 | 归因 | 处置 |
|---|---|---|
| 开罐/拉环瞬间穿帮 | **能力边界**（物理交互稳定性是已知弱项） | 明说提示词救不回来 → ① 拆两段跳过开启瞬间 ② 改微距只拍局部 ③ 固定 seed + 物理约束句 + best-of-3 |
| 液体倾倒断流 / 果冻感 | **能力边界** | 同上；补丁句「液体流线连续无断裂，以真实速率流动」只能缓解 |
| 冰块/融化降级为静态 | **能力边界** | 改成"液面已有冰块轻微晃动"的结果态，不拍融化过程 |
| 手指数量错 / 多手 | 提示词写法 | **加**「双手始终在画面内且可数，动作简洁」；减少同时进行的手部动作 |
| 布料/服装塌陷失真 | 提示词写法 | **加**面料动态词（垂坠/硬挺不塌/褶皱随步伐开合）+「版型轮廓保持清晰」 |

### E. 空间 / 比例（wan3.0 已知弱项）

| 症状 | 归因 | 最小补丁 |
|---|---|---|
| 人与商品比例失衡 | **能力边界 + 写法**（有比例失衡的已知记录） | **加**「人物与商品的相对大小比例全程稳定」+ 给具体参照（如"商品高度约为手掌长度"） |
| 躺卧/朝向反了 | 同上 | 显式写朝向：「头部朝画面左侧，身体平躺，面部朝上」 |
| 人物站位漂移 | 提示词写法 | 给显式画面坐标：「画面左侧三分之一处」「中央」「右侧偏后」 |

### F. 镜头 / 参数

| 症状 | 归因 | 最小补丁 |
|---|---|---|
| 说了固定机位还是在动 | 提示词写法：只写了一次 | 前缀「固定镜头」+ 结尾「机位与焦距全程不变」，写两遍 |
| 出来是横屏，要竖屏 | 参数不匹配 | `ratio=9:16`，**不要**在提示词里写"竖屏"，模型不吃；`ratio` 默认是 `adaptive` |
| 时长不对 / 动作没做完 | 参数不匹配 | 5s ≈ 1 个主动作；或用 `duration=-1` 智能时长 |
| 画质糊 | 参数不匹配 | `resolution` 提到 `1080P`（1.2 元/秒，先算成本） |
| 报 `media type conflict` | 形态选错 | 全能参考与首/尾帧互斥，二选一 |
| 报 `duration exceed` | 参数不匹配 | 有视频输入时「输入总时长 + 输出 ≤30s」 |
| 504 ResponseTimeout | 工程问题非提示词 | 底层空闲超时 3600s，单次 duration 别贪长；拆段重跑 |
| 自己切了分镜 / 中途跳镜 | 提示词写法：没声明分镜 | 不写分镜模型自行发挥 → **加**「生成单镜头」或「一镜到底」；要多镜就写「第1个镜头[0-3秒]…」 |

### G. 视频编辑 V2V

| 症状 | 归因 | 最小补丁 |
|---|---|---|
| 改了一处，其他地方也跟着变 | 提示词写法：没写保护句 | 句尾**加**「其他保持不变」 |
| 模型把原片重演了一遍 | 提示词写法：把原片内容又描述了一遍 | **删**所有对原画面的复述，只留「编辑对象 + 编辑行为」 |
| 换 SKU 后接缝明显 / 透视不对 | 素材问题非提示词 | 换一张**同角度同光位**的参考图；提示词救不回来 |
| 改台词后音色变了 | 提示词写法：漏了保音色句 | **加**「保持人物音色和语气」，与台词写在同一句 |
| 全局调色后商品本色被改掉 | **能力边界**（色号敏感品类） | 明说全局调色不适用于口红/粉底/油漆/布料；改走元素替换或重拍 |
| 视频延长后从头再演一遍 | 提示词写法：延长时复述了已有画面 | **删**已有画面描述，只写「后续发生什么」 |
| 报 `duration exceed` | 参数不匹配 | 输入视频总时长 + 输出 `duration` ≤ 30s |

### H. 多镜头结构 / 参考片反推

| 症状 | 归因 | 最小补丁 |
|---|---|---|
| 某个分镜被草草带过 / 某段被拖长 | 提示词写法：时间戳之和 ≠ `duration` | 重排时间戳做到首尾相接、求和等于 `duration`；单镜不少于 2s（`prompt-craft-discipline.md` §1） |
| 镜头之间跳戏、上一镜结束状态接不上 | 提示词写法：每段缺"结束状态" | 每段补齐**起始状态 + 可见动作 + 镜头拍法 + 结束状态**，并让上段结束状态 = 下段起始状态 |
| 5s 里塞了三个动作，全都没做完 | 提示词写法：段数超卡尺 | 按段数卡尺压缩：5s→1 镜、8–10s→2–3 镜、15s→3–4 镜；一段只留一个主动作与一个主运镜 |
| 同一段里镜头一会儿固定一会儿环绕 | 提示词写法：一段写了多个主运镜 | 一段只保留一个主运镜，其余运镜拆到下一段 |
| 照着参考片做，成片多出原片没有的动作/对白 | 提示词写法：反推时做了创意外推 | 只写画面里能确认的动作；要加戏另建"创意延伸版"，不要覆盖直接反推版（`prompt-craft-discipline.md` §5） |
| 反推出来节奏对不上原片 | 提示词写法：按平均时长切段而非真实切点 | 逐帧核真实剪辑切点，按真实切点写时间戳；区分硬切与无缝转场 |
| 多素材时职责串了（背景图的元素跑进主体） | 提示词写法：缺素材职责声明 | 每个素材写全**编号 + 正向职责 + 生效时段 + 禁止迁移项**（`prompt-craft-discipline.md` §2） |

### I. 美妆 / 上妆 / 涂抹类（刷睫毛、涂口红、上粉底等特写演示）

这类是"人物特写 + 精细手部操作 + 前后对比"的叠加，wan3.0 的左右锚点、对比保持、多状态产品是集中翻车区（睫毛膏类 case 迭代实测提炼）。

| 症状 | 归因 | 最小补丁 |
|---|---|---|
| 涂刷特写左右侧互换（刷了这只眼，下一镜刷到另一只 / 涂到另一边嘴角） | 提示词写法 + 能力边界：特写只给单侧，模型丢失左右锚点 | **改**成「双眼 + 鼻梁始终同框」的构图（**禁单眼/单侧大特写**，这是根因）；**删**「从角色右侧拍」「仅正面机位」这类观众视角/机位锚定（实测均无效）；**加**「刷头只接触画面左侧那只眼（角色右眼），全程不换边」——用**画面左右**而非"角色左右"下锚，模型更认 |
| 前后对比在后续镜头被抹平（刷过的睫毛和没刷的又变得一样长） | 提示词写法：缺**全局保持锁** | **加**跨镜头全局锁：「已刷过的一侧睫毛黑浓卷翘、明显更长更密，未刷侧短、稀、塌陷接近素颜，两侧长度与浓密度任何时候都不得相近，对比保持到片尾」；把它挂在声音层/人物描述句上，确保每个双眼镜头都受约束 |
| 双头 / 多段产品被拆成两个单件（双头睫毛膏变两根单头圆柱、双头刷各拿一根） | 提示词写法 + 参考图：参考图含同一产品两个状态，或缺构图锚定 | 参考图**裁到只剩单一状态**（见 A 类，根因）；**加**「画面构图与参考图同构，这是一支 XX，只操作一端、另一端保持原状」；**加**正面计数「部件共 N 件，不多不少」；**不要**写「不得拆成两件」（否定存在锁会删镜头，见零节 #8） |
| 拔盖/开盖动作把整支产品或盖子复制成两份 | 提示词写法：否定存在锁反噬 + 参考图双状态 | 同上；关键是**正面计数 + 同构 staging**，并显式写「只拔下一端的盖子，另一端盖子保持拧在管身上不动，拔下的盖子是空的，刷头留在管身上」 |
| 口播长台词丢字 / 整段丢人声 | 提示词写法：台词太长 / 声音层没锁死人声 | 台词**逐句独立成句、逐字照读**，并点名「必须出现人声、不得省略任何一句」；台词字数 ≈ `duration × 4`；仍不稳就**并行多 seed 抽有人声且逐字干净**的一版（判台词只认逐字 ASR 转录） |

## 二、最小补丁的写法规范

只列改动，不重写全文：

```
【最小补丁】
改：镜头快速环绕商品一周          → 镜头绕 @图片1 缓慢环绕 180 度
删：杯身是哑光陶瓷，米白色，手工收口边缘（参考图已承载）
加：商品轮廓与比例全程保持稳定，正面 logo 始终朝向镜头且保持清晰不形变
加：全片无台词，无背景音乐，仅保留极轻的室内环境底噪
【复测建议】seed 固定为 <上次的 seed>，只改上述句子做 A/B；若仍穿帮 → 走拆两段方案
```

**禁止**：一次性改 5 处以上、把补丁写成新一版完整提示词、加一堆没有针对性的"高质量、8K、电影级"堆砌词。

## 三、A/B 复测纪律

1. 一次只动**一个变量**（一句话 或 一个参数）
2. `seed` 固定，否则分不清是补丁生效还是随机波动
3. 高危动作类 case 用 **best-of-3**：同 prompt 跑 3 个不同 seed，挑最好的，并记录成功率
4. 批量复测 → 每个 case 独立记 task_id，**禁止混用**；结果落 `manifest.csv`
5. 结论写法：「补丁 X 后 3/3 未穿帮」这种可复现口径，不要写"感觉好多了"
6. **出片后先验真实格式再判**：`ffprobe` + `file` 核实际编码（扩展名会骗人，`.wav` 常是 M4A/AAC）；口播用 ASR 工具**逐字**转录核台词，**不要用宽松的多模态理解工具判台词与左右**（会把口胡"纠正"回原文、误报左右一致）；多帧抽样用 PIL 竖排联络表一次看完（涂刷侧、前后对比、拔盖各取关键秒）。音频峰值 < -26dB 属近静音，等于丢人声。
