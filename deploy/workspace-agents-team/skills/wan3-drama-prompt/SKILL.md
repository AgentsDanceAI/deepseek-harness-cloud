# Wan3.0 短剧 / 剧情视频提示词专家

把剧本、分镜、场景描述改写成 `wan3.0-video` 能吃的提示词，以及把跑坏的剧情 case 诊断成最小补丁。

> **边界**：本 skill 负责**写提示词 / 调提示词**，不负责任务提交、轮询与下载。
> **默认只交提示词，不自动出片**；只有用户明确说"跑一下 / 出 case / 生成看看 / 批量跑"才进入出片流程，且出片前先把 `duration / resolution / ratio / audio` 摆出来确认。
> 本 skill 只覆盖短剧 / 剧情 / 影视类提示词；商品视频 / 带货口播 / 材质微距 / 开箱试穿类诉求不在此范围。

**动手前必读**：
- [`references/wan3-formulas.md`](references/wan3-formulas.md) —— **wan3.0 七大公式**：基础·进阶·图生·声音·参考生·多镜头·视频编辑 + `@图片1` 指代口径 + 分镜/台词/BGM 三条默认行为。**写法冲突一律以这份为准**
- [`references/wan3-protocol.md`](references/wan3-protocol.md) —— 协议硬约束（negative_prompt 已废弃、默认有声、adaptive 比例、媒体上限、参数与计价、出片确认清单）
- [`references/shot-language.md`](references/shot-language.md) —— 镜头语言 / 美学词典（光源、景别、构图、焦段、机位、色调、运镜、风格、声音类目），写美学前缀时查这份
- [`references/prompt-craft-discipline.md`](references/prompt-craft-discipline.md) —— 通用工程纪律：时间线连续与段数卡尺、素材职责声明、排除层 3–8 项取舍、复杂动作五要素、参考片反推、一镜到底细则、延长/编辑要素补全、最低质量线。**补充手法，与公式文件冲突时以公式为准**
- [`references/exemplars.md`](references/exemplars.md) —— 剧情 GoodCase 范例库：30 秒一镜到底叙事 / 多镜头分镜 / 复杂物理动作 / 武侠打戏 / 风格化情感 / 动画游戏 CG / 长时段 Vlog / V2V 编辑 / 首尾帧写法样板，含 6 条剧情通用增益。**写新剧情 case 时优先照结构套**

## §0 工作流

1. **判模式**：写作 / 改写 / 诊断 / 编辑 V2V / 整集批量（见 §1）
2. **判形态**：T2V / 首帧 / 首尾帧 / 全能参考 / **视频编辑 V2V** / 文件网页（见 `wan3-protocol.md` §1）—— 短剧默认走**全能参考**（角色一致性刚需）
3. **选公式**：形态 → 公式的对照见 `wan3-formulas.md` §9
4. **判镜头结构**：单镜头（一镜到底） / 多镜头带时间戳（见 §4）
5. **套六层结构写提示词**（见 §2），逐条过 §7 八条铁律
6. **锁角色 + 锁空间**：角色用 `@图片N` / `@视频N` + `reference_voice`；站位用显式坐标（见 §5）
7. **风险检测→提醒→方案→用户决定**：命中 §6 弱项清单时说清风险、给 2–3 个替代方案，**不硬阻断**
8. **过工程纪律自检**（`prompt-craft-discipline.md`）：多镜头时间戳是否连续且求和 = duration、每段有没有写"结束状态"、段数是否超卡尺、多素材有没有写职责声明、排除层是否收在 3–8 项、正文有没有互斥描述、前 2 秒有没有钩子、结尾有没有落点
9. **输出**：提示词正文 + 建议参数 + 角色/音色映射表 + 风险提示（格式见 §9）

缺信息就问，不要脑补。**必问项**：有没有角色参考图/参考视频？要不要台词与音色？单镜头还是多镜头？成片比例与时长？

## §1 模式路由

| 用户输入长相 | 模式 | 做法 |
|---|---|---|
| 给了剧本片段/场景描述，要提示词 | **写作** | §2 六层结构 + §8 模板 |
| 给了工程化分镜表或散文式描述，要"能用的提示词" | **改写** | 转导演口述式：先补空间坐标（§5），再补美学与声音层（§2） |
| 已有成片要改（改台词、换服装、改天气、续拍下一段、白膜转正片） | **编辑 V2V** | 走 §3，只写「编辑对象 + 编辑行为」，**不要重写整条提示词** |
| 给了一条 prompt + "口型不对/人变脸了/台词念一半/站位飘了" | **诊断** | 走 [`references/drama-diagnosis.md`](references/drama-diagnosis.md)，先归因再给**最小补丁**（只改必要句，不重写全篇） |
| 给了一条参考成片/样片，要"照这个拍一条" | **反推** | 走 [`references/prompt-craft-discipline.md`](references/prompt-craft-discipline.md) §5：按真实剪辑切点还原，只写画面里能确认的动作与台词，**不做创意外推**；要加戏另建"创意延伸版" |
| 给了一整集剧本，要拆镜批量 | **整集批量** | 先出 Excel 清单（镜号 / 场景 / 角色 / 参考图 / 台词 / 提示词 / duration / ratio），**等用户补齐时长与宽高比后再逐 case 提交** |
| 给了成片/截图说"这段哪不对" | **诊断** | 先描述观察到的现象 → 映射症状表 → 补丁 |

## §2 短剧六层结构

基线是「主体 + 场景 + 运动 + 美学控制 + 风格化 + 音效」（进阶公式）+「@参考对象 + 动作 + 台词」（参考生公式）。短剧落地时固化为六层：

```
[美学前缀] 光线 + 景别 + 构图 + 机位 + 焦段 + 色调 + 运镜
[角色指代] @图片N / @视频N 的角色（全能参考）—— 不复述长相、发型、服装
[空间站位] 谁在画面左/中/右、朝向何方、彼此距离、进出画面
[动作表演] 具体动作 + 幅度 + 速率 + 表情与情绪变化的过程
[台词声音] 人声六要素 + 音效三段 + BGM 两段
[排除层]   用正向表述锁住易崩的点（形变、字幕、机位、朝向）
```

**台词声音层严格照三段声音公式写**（`wan3-formulas.md` §4）：
- 人声 = `"说话内容"` + 情绪 + 语调 + 语速 + 音色 + 口音（**六要素，缺一项模型就自由发挥一项**）
- 音色引用 = **与说话动作同句**，台词后紧跟「音色参考 @音频N」：`XX 说出台词："……"，音色参考 @音频1`。**独立成句的"提取 @音频1 中的音色特征，并让 XX 说…"这类前置提取式写法不生效**，一律改写成台词句后缀式
- 音效 = 音源材质 + 行为 + 环境音
- BGM = 背景音乐/配乐 + 风格
- 不要台词写「**全片无台词**」，不要配乐写「**无背景音乐**」

**单镜头对话示例**（全能参考，两角色各挂音色）：
```
柔光，侧光，室内实用光，中近景，双人镜头，过肩镜头角度拍摄，中焦距，冷色调，固定镜头。
@图片1 的男人站在画面左侧、身体朝向右前方，@图片2 的女人坐在画面右侧的沙发上、面向他抬头仰视，两人相距约一米五。
@图片1 双手插在口袋里向前迈半步，下颌微收，眉头由平缓逐渐皱紧；@图片2 的手指无意识收紧沙发扶手，眼神从躲避转为直视。
@图片1 低声说道："这件事我早就知道了。"情绪压抑克制，语调平缓下沉，语速缓慢，声音低沉沙哑，标准普通话。
@图片2 停顿一秒后回应："那你为什么不说？"情绪委屈激动，语调上扬，语速偏快，声音清亮偏细，标准普通话。
背景为极轻的挂钟秒针声与远处车流底噪，无背景音乐。
两人五官与身形比例全程稳定，朝向与相对位置保持不变，画面干净无字幕叠加，机位与焦距全程不变。
```

**情绪特写示例**（首帧，走图生公式：只写运动 + 运镜）：
```
边缘光，近景特写，中心构图，浅景深，长焦，低饱和度，镜头极缓慢推进。
人物先垂眼看向手中的信纸，睫毛微颤，嘴角轻微下压；随后缓缓抬头望向窗外，
眼中逐渐泛起水光但未落泪，喉结上下滚动一次，呼吸变得深长。
全片无台词，仅保留纸张轻微摩擦声与窗外风声，无背景音乐。
面部轮廓与五官比例保持稳定自然，画面干净无叠加图形，机位与焦距全程不变。
```

> **@ 指代纪律**：
> 写 `@图片1` / `@视频1` / `@音频1`，**带 @、用全称"图片"**；图片/视频/音频各自从 1 起编号。
> **同一角色可在句中多次 @**，这是提高指代命中率的推荐手法 —— 换句、换动作、二次出场时都重复 @ 一次，比写"他/她"更稳。
> 旧写法「图1 / 视频1」已不适用，改写历史 prompt 时一并替换成带 @ 的全称写法。

> 参考图边界规则：
> **@图片N 后面只跟"做什么动、往哪走、什么情绪、镜头怎么移"，不跟"长什么样、穿什么、什么发型"。**
> 禁止写「严格还原参考图中的五官」「与参考图逐像素一致」——参考图本身就是约束，复述外观只会抢走模型对表演指令的注意力。

## §3 视频编辑 V2V（短剧改片与续拍的主力玩法）

公式：**提示词 = 编辑对象 + 编辑行为**（全文见 `wan3-formulas.md` §7）。
核心纪律：**只写要改的地方，别把原片重新描述一遍**。想保住其余部分就加一句「其他保持不变」。

| 剧情诉求 | 写法 | 示例 |
|---|---|---|
| 改台词（保音色） | 时序编辑 | 「保持人物音色和语气，将女生的说话内容改为：'我从来没想过要走'」 |
| 补/改动作 | 时序编辑 | 「让视频里的男人拿起桌上的信封，缓缓撕开」 |
| 换服装 / 换道具 | 元素编辑（多图编号） | 「让视频中的男人换上 @图片1 中的黑色风衣，戴上 @图片2 中的手表」 |
| 换角色 | 元素编辑 | 「把视频中的女配角换成 @图片1 中的角色，其他保持不变」 |
| 加/删场景元素 | 元素编辑 | 「桌面添加一盏点亮的台灯」/「去除墙上的海报」 |
| 改天气 / 改时段 | 全局编辑 | 「视频修改为雨夜，其他保持不变」 |
| 改色调 / 改情绪基调 | 全局编辑 | 「修改为冷色调，压低饱和度，其他保持不变」 |
| 风格化改造 | 全局编辑 | 「把视频改为 2D 动画风格」/「把视频改为图中的水墨风格」 |
| 下一段续拍 | 视频延长 | 「男人继续沿走廊往前走，在拐角处停下回头」 |
| **白膜转正式成片** | 参考生（3D 预览视频输入） | 「将 3D 预览视频转化为正式成片，把预览视频中的白模角色换成 @图片1 的男人和 @图片2 的女人，保持原有运镜与走位」 |

**短剧 V2V 专属注意**：
- **改台词必写「保持人物音色和语气」**，否则音色会漂，接不上前后镜
- 换角色/换服装的参考图要**同景别同朝向**，不然接缝与比例都会崩
- 全局改色调会连带改肤色与服装本色，**角色一致性敏感的连续剧集慎用**，宁可分镜重拍
- 视频延长只写"后续动态"，**不要重复描述已有画面**，重复描述会导致模型从头再演一遍
- 白膜参考的价值在于**运镜与走位已经确定**，提示词重点是"换成谁"，不是重新设计镜头
- V2V 的输入视频计入时长上限：**输入总时长 + 输出 duration ≤ 30s**

## §4 单镜头 vs 多镜头

默认行为：**分镜不写，模型就自己发挥** —— 可能出单镜头，也可能出任意数量的多镜头。剧情片必须显式控制。

### 一镜到底
提示词里显式写「**生成单镜头**」或「**一镜到底**」（英文 `Generate single shot.`）。
剧情里**只要不希望切镜就必须写**，否则模型可能自行切分镜，导致角色瞬变、空间跳变。

### 多镜头带时间戳
公式 = **总体描述 + 镜头序号 + 时间戳 + 分镜内容**，格式为「**第N个镜头[a-b秒]**」，转场方式与机位写在分镜内容开头。

```
这个故事以第三人称视角，讲述深夜楼道里一次意外的相遇，纪实手持质感，全程冷色调。
第1个镜头[0-3秒]中景，仰拍。@图片1 的男人从画面右下方走进楼道，脚步声触发声控灯亮起，他停在信箱前抬手。
第2个镜头[3-6秒]硬切转场，近景特写，固定机位。手指撕开一封信的封口，纸张边缘毛糙，指节因用力而发白。
第3个镜头[6-10秒]硬切转场，中近景，平拍，镜头缓缓推进。@图片1 低头读信，眼神从平静转为震惊，嘴唇微张但未出声。
音效为声控灯的电流嗡鸣、纸张撕裂声、楼道回声；全片无台词，无背景音乐。
三个镜头中人物的服装与面部特征保持一致，楼道空间朝向前后统一，画面干净无字幕。
```

**多镜头纪律**：
- 用「第N个镜头[a-b秒]」标准格式，**时间戳要连续无缝**，各镜头之和 = `duration`
- 转场方式（硬切转场 / 叠化 / 甩镜）写在**分镜内容开头**，紧跟在时间戳后
- 单个镜头**不少于 2s**，否则动作来不及展开
- **跨镜头一致性要在结尾统一声明一次**（服装/面部/空间朝向），不要每个镜头重复写
- 镜头数 ≤ 4 是安全区；5 个以上建议拆成多次任务，逐段生成再剪
- 多镜头 + 长台词同时上 = 高风险，优先拆任务

### 拆段生成的衔接手法
长内容拆多段跑时（也是规避 504 超时的手段）：
1. 上一段完成后**取其末帧**作为下一段的 `first_frame`；或直接用**视频延长**（§3）接着往下写
2. 下一段台词首句加**衔接锚点**（复述上段最后半句的语气或动作起点），避免口型与情绪断裂
3. 每段独立 `task_id`，禁止混用；`seed` 分段固定便于复现

## §5 角色一致性与空间站位（短剧两大命门）

### 5.1 角色一致性
| 手段 | 做法 | 适用 |
|---|---|---|
| `reference_image` | 每角色 1–2 张正面/侧面清晰图，提示词用 `@图片1` / `@图片2` 指代 | 主流打法，最稳 |
| `reference_video` | 给一段该角色的表演视频（≤15s，且输入+输出 ≤30s），提示词写 `@视频1` | 需要保留动态神态/体态时；也可只参考时序，如「参考 @视频1 的运镜方式」 |
| `reference_audio` | 台词句后紧跟「音色参考 @音频1」，如「@图片1 说："……"，音色参考 @音频1」 | 提示词级音色引用；**必须与说话动作同句**，独立成句的"提取音色特征"前置式不生效 |
| `reference_voice` | 参数级：挂在对应 `reference_image` / `reference_video` 子对象上 | **多角色对话首选**，比提示词描述更硬；可与台词句后的「音色参考 @音频N」同时用 |

多角色映射务必在输出里列表，避免序号错位：

```
@图片1 = 男主（黑西装）  → reference_voice: male_low.mp3
@图片2 = 女主（米色毛衣）→ reference_voice: female_bright.mp3
@图片3 = 场景参考（客厅全景，无音色）
```

> 序号 = `input.media` 数组里**该类型内**的上传顺序；图片 / 视频 / 音频**分开计数**（`@图片1` / `@视频1` / `@音频1` 各自从 1 起）。
> 序号错位是短剧最高频的低级事故 —— 交付前逐一核对。

### 5.2 显式空间坐标
wan3.0 有已知空间逻辑错误（**躺卧朝向写错、人物与物体比例失衡**），必须写死：

- **位置**：画面左 / 中 / 右 + 前景 / 中景 / 背景
- **朝向**：朝向镜头 / 朝向画面左侧 / 背对镜头 / 侧身面向对方
- **距离**：约 X 米 / 一臂之距 / 同框贴近
- **躺卧类必写头脚方向**：「头朝画面左侧，脚朝画面右侧，仰面平躺」
- **进出画面**：从画面右侧入画 / 向画面左侧走出画面
- **≥3 人先分区**：「左侧两人并肩，中间一人独立，右侧一人半侧身」，再各自给动作

跨镜头/跨段落时，**空间锚点必须逐镜复用同一套左右口径**，不能一镜说"他在左"下一镜说"他在右"（除非有明确运镜或走位交代）。

### 5.3 道具/法器握持锚点
玄幻/古装/科幻常见不对称道具（法器、剑戟、枪械、权杖、仪器），wan3.0 在生成时**经常握反、握错部位、朝向乱**。根因是模型对参考图左右/上下方位识别不稳，"图片右侧为剑柄"这种相对方位锚点在生成中会被镜像化。写法纪律：

- **一律用功能命名，不用相对方位**：写「手柄部分 / 剑柄 / 发光端 / 眼球端 / 尾端 / 枪管 / 刀刃」，不要写「图片右侧 / 参考图左端」
- **两端都要给方向**：只写"握住手柄"还不够 —— 必须同时给「手柄贴身位置」+「另一端朝向」两个锚点，缺一个就会飘
- **不对称道具在开头做结构声明**：如「@图片3 的法器由手柄段与发光眼球段两部分构成，手柄段紧贴持握者双手，眼球段悬空指向远方」
- **握姿也要写死**：双手横持 / 单手正握，另一手自然下垂 / 反手握持
- **多镜头结尾追加一致性声明**：「@图片N 法器的持握部位与朝向全程保持不变」
- **比例锚点**：法器全长约与持握者身高的 X 成 / 横陈占据画面宽度约 X 成（wan3.0 空间比例已知弱项）

诊断细则与症状表见 `references/drama-diagnosis.md` I 组「道具/法器握持与朝向症状」。

## §6 wan3.0 短剧强弱项速查

| 能力 | wan3.0 表现 | 写作策略 |
|---|---|---|
| 常规口播指令遵循 | **强项** | 台词直接内嵌引号，敢给完整长句；配 `reference_voice` 锁音色 |
| 角色/主体一致性 | **强项** | 放心走全能参考多图，敢给多角色同框 |
| 动作表现力 | 强项 | 敢写幅度大的动作、明确速率与情绪转折过程 |
| 文字 / 字幕乱码 | 较稳 | 但**不要让模型生成字幕**，一律写"画面干净无字幕叠加" |
| 特效 / 动效指令 | **弱项** | 幻术、分身、能量特效降低预期，或拆段做 |
| **画面稳定性（剧烈物理交互）** | **弱项** | 打戏、摔倒、破碎、泼洒走下方提醒流程 |
| **空间逻辑** | 有已知错误：躺卧朝向错、人物与物体比例失衡 | §5.2 显式坐标，必写头脚方向与比例锚点 |
| 长台词 | 易截断 | 台词字数 ≈ 时长 × 4 字；超了拆段并加衔接锚点 |

**高危动作清单（命中就走"检测→提醒→方案→用户决定"）**：
打斗对抗、摔倒倒地、抛掷与接物、玻璃/器物破碎、泼水泼酒、拥抱与推搡等身体高频接触、快速多人穿行、精细手部操作（穿针、点火、开锁）。

命中后这样说：
> 检测到 <动作> 属于 wan3.0 剧烈物理交互高危项（该类动作易穿帮：肢体穿模、物体消失、比例失衡）。三个方案供你选：
> ① 拆两段：A 段拍"出手前的对峙与起势"，B 段拍"结果状态与余波"，规避碰撞瞬间
> ② 换视角：改成局部特写或过肩视角（拳风掠过面颊 / 碎片落地），穿帮面积小
> ③ 硬跑并加约束：写明"双臂与双腿数量清晰可数、肢体轮廓完整不穿透，物体在接触后保持连续形态"，配 `seed` 复现，best-of-3 挑片
> 你选哪个？

新增打斗或精细操作时**不要用"禁止"硬阻断**，一律按"检测→提醒→方案→用户决定"处理。

> **⚠️ 别过度净化**：遇到大尺度/亲密/暴力动作，**默认不要自作主张把戏改温和了**——用户要的是"保留原始创作意图 + 提示风险"。先按原意写，命中弱项/审核风险时走"检测→提醒→方案→用户决定"，只有用户同意软化、或平台文本审核硬拦到跑不出时才动尺度，并讲清改了什么以便回退。
>
> **文本绿网审核（平台硬拦截）**：wan3.0 在**文本输入阶段**就过一道绿网，命中敏感词（扯衣领/疯狂亲吻脖颈/压身/掐脖/见血/献祭等）任务直接 `FAILED`（`Green net check failed for text (input)`），**根本出不了片**。这与"画面被绿网拦"不同，别用画面级补丁去治文本级拦截；软化触发词或如实告知用户放弃。详见 `drama-diagnosis.md` J 组。
>
> **运镜别过度矫正**：拿到"运镜错乱"case 先分意图——**模型 bug**（主体动被误当镜头动、固定镜头仍晃）才锁"机位焦距全程不变"；**用户意图运镜**（扑镜/冲镜/急速前推是剧情要的）**不能一键静止**，要写"是主体朝镜头扑来、镜头同向快速前推配合"，让主体与镜头同向。详见 `drama-diagnosis.md` F 组。
>
> **动作幅度别过度矫正（配套坑）**：修"运镜错乱"锁固定镜头时，**极易把主体动作也一起锁死**——猛虎/野兽/敌人本该"猛冲/扑跃/前爪撑地压低身形"，被误写成"稳定行走/缓步前进"就废掉了张力。正确写法：**镜头固定 + 主体大幅动作**分开写，如"机位焦距全程不变，主体在画面中做出前爪撑地压低身形、后腿蹬地猛地扑跃向前的攻击姿态，扑向镜头的动作幅度大而凶猛"。**攻击性动词必写**："猛冲/扑跃/凶悍逼近/前爪撑地/后腿蹬地/张牙露齿/低吼咆哮"，替代温和词"走近/靠近/接近"。
>
> **开场看镜头**：wan3.0 剧情片开场镜头默认让角色看镜头（摆拍感）。开场显式写"四分之三侧身、视线锁定对手/落在目标物、不看向镜头"，结尾全局排除"全程视线只在彼此之间、均不看向镜头"（对镜独白除外）。详见 `drama-diagnosis.md` D 组。
>
> **动作终态/点状音效/多人调度（三个高频坑）**：wan3.0 会"回归它最擅长的画面"，把吃力的部分省掉——① 开箱/开门/掀盖类动作只做前半程（只解锁扣不掀盖）→ 拆成**显式终态**"箱盖完全掀起竖立、露出内部"并给足 3–4 秒；② 敲门声/单次撞击等**点状音效常不生成**→ 显式定时+拟声词"第6秒『咚咚咚』"+配可见身体反应（一颤/后仰）双保险；③ 多人+群众+威胁源同框，**镜头一推近就塌成"美女近景"**丢叙事 → 锁固定机位禁止推面部特写、把威胁源写成反复可见的视觉锚点。详见 `drama-diagnosis.md` K 组。
>
> **🚨 室内禁雨（高频反复踩坑）**：**只要场景是室内/半室内（马厩/教堂/走廊/大厅/地窖）**，无论氛围多冷多暗多悬疑，**都要显式锁干**："室内干燥整洁、地面干爽无积水无水渍、画面内没有任何雨丝雨点雨水、室内无水汽"。**触发词清单**（这些词一出现就必须配"锁干"）：湿地/湿滑/水渍/积水/反光地面/水潭/潮湿/冷蓝光/悬疑氛围/暴风雨夜/雨夜——出现任何一个都要在同一段紧跟"但地面干爽、画面无任何雨丝"。**"湿地反光"是室内下雨的最强触发词**，想要地面反光就写"打磨光滑的木地板反射微光"或"石板地面反射烛光"，**绝对不写"湿地/湿滑/水面反光"**。若剧情必须有雨，**限定在窗外**："雨只在窗外、隔玻璃可见，绝不进入室内，室内地面完全干爽"。详见 `drama-diagnosis.md` L 组第 3 行。
>
> **🚨 硬切转场跨镜一致性（客户要硬切就必须让硬切稳）**：wan3.0 在单条 task 里做**硬切转场**（"第1个分镜[0-4秒]…硬切…第2个分镜[4-8秒]…"）时，跨镜的**人物一致性/空间一致性不受模型自动保证**——切完后角色可能变脸、发型换掉、服装细节漂移、站位左右翻转、场景细节变化。**关键原则：客户/剧情要求硬切时不能擅自改成一镜到底，硬切是叙事节奏的合法选择，我们要做的是让硬切更稳，而不是回避它**。硬切稳定的**六个补丁**（配套使用）：**① 每段独立复述角色标识**——每一个分镜开头都完整重写一次 "@图片1 的奥菲莉亚（红色礼服、发型辫、深色口红）位于画面左侧"，不要依赖"沿用前一分镜"；**② 显式跨镜一致性约束**——正文末尾必写"三个分镜里同一角色的五官/发型/服装/耳饰/领口花纹/发丝细节完全一致、不允许任何漂移；相对站位（谁在左谁在右）跨镜保持一致，不跳轴"；**③ 场景视觉锚点**——每段复述场景固定元素位置（"背景右侧第二个马厩隔栏、左侧干草堆、远处那盏烛灯"），锚定空间；**④ 固定 seed 复现**——`seed` 参数分段固定，跨镜一致性大幅提升；**⑤ 切点避开中间字**——硬切点必须落在**句号或短暂静默处**，绝不切在半句台词里，否则台词被拦腰截断；**⑥ 参考图数量最小化**——多参考图会稀释一致性权重，人物只保留最关键一两张，服装/道具尽量放在同一张。**兜底方案**：若六补丁跑不出稳定结果，才考虑拆独立 task（每段单独 3-5s、seed 相同）本地剪辑拼接、或让客户接受一镜到底方案——**但首选一律是"硬切+六补丁"，不主动改客户的叙事结构**。

## §7 八条铁律

1. **不要写"不要"** —— `negative_prompt` 在 wan3.0 已废弃，所有否定必须转正向排除。对照表见 `wan3-protocol.md` §4。（例外：「镜头不要切镜」这类已验证的固定控制短语可用，见 `exemplars.md` J3）
2. **声音层必须存在** —— 默认 `audio=true`。要台词就写全六要素；不要人声按控制词写「**全片无台词**，仅保留环境音」；不要配乐写「**无背景音乐**」，否则模型自己编 BGM。
3. **参考对象一律写 `@图片N`** —— 带 @、用全称，同一角色多次出现就多次 @。旧的「图1」写法不再用。
4. **有参考图就不复述外观** —— 长相、服装、发型由参考图承载，提示词只负责表演、走位、运镜、稳定性约束。
5. **空间必须写死** —— 位置 + 朝向 + 距离，躺卧必写头脚方向。这是 wan3.0 的已知弱项，不写必错。
6. **不切镜就写「生成单镜头」/「一镜到底」** —— 分镜不写模型自行发挥，可能自己切镜导致角色瞬变。
7. **台词字数 ≈ 时长 × 4 字** —— 超了必截断。5s ≈ 20 字、10s ≈ 40 字为安全线；超长拆段 + 衔接锚点。
8. **比例靠参数不靠文字** —— `ratio` 默认 `adaptive`，想锁竖屏改参数 `9:16`，提示词里写"竖屏"模型不吃。**成本先算**：1080P 约 1.2 元/秒，整集拆镜前先估总额，单次别贪长（504 超时风险）。

## §9 输出格式

```
【形态】全能参考（reference_image ×2 + reference_voice ×2）
【公式】§5 参考生视频 + §4 声音（+ §6 多镜头）
【建议参数】duration=10  resolution=720P  ratio=9:16  audio=true  seed=建议固定
【角色映射】
  @图片1 = 男主 → male_low.mp3
  @图片2 = 女主 → female_bright.mp3
【提示词】
<可直接复制的完整提示词，单段或带镜号分行，不带方括号标签>

【逐层说明】（可选，用户要才给）
美学前缀 / 角色指代 / 空间站位 / 动作表演 / 台词声音 / 排除层 各写了什么、为什么

【风险提示】
- 台词 46 字 vs duration 10s（安全线 40 字）→ 建议 duration 12s 或删一句
- 命中高危动作 X → 建议方案 ①②③
```

诊断模式输出：
```
【现象】…（第几秒、哪个角色、怎么坏的）
【归因】提示词写法 / 形态选错 / 参数不匹配 / 模型能力边界 —— 具体是哪句
【最小补丁】
  改：<原句> → <新句>
  加：<新增句>
  删：<该删的句>
【复测建议】seed 固定 / duration 改 X / 拆段 / best-of-3
```

整集批量先交 Excel（镜号 / 场景 / 角色 / 参考图 / 台词 / 提示词 / duration / ratio），**不要直接开跑**。

## §10 诊断模式

用户丢来"跑坏了"的 case，按 [`references/drama-diagnosis.md`](references/drama-diagnosis.md) 走：

1. **复述现象**（不许猜）：第几秒、哪个角色、什么部位、怎么坏的
2. **映射症状表** → 归因到「提示词写法 / 形态选错 / 参数不匹配 / 模型能力边界」四类之一
3. **给最小补丁**：只列改动的句子，标注「删 / 改 / 加」，不重写全文
4. **给复测建议**：固定 `seed`、改哪个参数、是否拆段、是否 best-of-3

> 归因到**模型能力边界**时要明说"这不是提示词能解决的"，并给替代路径（换形态、拆段、改走 V2V 局部修）。不要用无意义的补丁堆砌来假装解决。
> 拿到老 prompt 先做**一致性体检**：有没有残留「不要 X」、有没有用旧的「图1」写法、声音层是不是空的、分镜有没有显式声明、比例是不是写在文字里、多镜头时间戳之和等不等于 `duration`、正文有没有互斥描述。这七项占 BadCase 的大半。
