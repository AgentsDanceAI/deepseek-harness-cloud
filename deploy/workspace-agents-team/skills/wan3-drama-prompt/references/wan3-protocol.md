# wan3.0-video 协议约束 —— 提示词侧必读

> **口径优先级**：公式与写法冲突时一律以 `wan3-formulas.md` 为准；参数与接口约束以本文件为准。
> 参数与限额随版本迭代可能调整，交付前以平台当前实际返回为准。

---

## 1. 一个模型，用法由 media 决定

只有一个 model name：`wan3.0-video`。文生 / 图生（首帧、首尾帧）/ 参考生 / 文件网页解析全部走同一入口，由 `input.media[].type` 决定形态。

| 形态 | media 组成 | 提示词该写什么 |
|---|---|---|
| T2V 文生 | 无 media | 全量描述：主体+场景+运动+美学+风格+声音 |
| I2V 首帧 | `first_frame` ×1 | **只写运动 + 运镜 + 声音**，不复述画面里已有的外观 |
| 首尾帧 | `first_frame` + `last_frame` | 只写**中间过程**如何从首帧过渡到尾帧 |
| 全能参考 | `reference_image` ≤10 / `reference_video` ≤5 / `reference_audio` ≤5 | 用 `@图片1` / `@视频1` / `@音频1` 指代 + 动作 + 台词，不复述外观 |
| 视频编辑 V2V | `reference_video` + 可选参考图/音频 | 只写**编辑对象 + 编辑行为**（换/加/删元素、改色调风格、改台词动作、续拍延长） |
| 文件/网页 | `file` ×1 或 `link` ×1 | 写"要做成什么样的视频"，内容由模型读取素材决定 |

**形态 → 公式对照**（公式全文见 `wan3-formulas.md`）：
T2V → §1 基础 / §2 进阶；首帧·首尾帧 → §3（运动+运镜）；全能参考 → §5（@参考对象+动作+台词）；
视频编辑 → §7（编辑对象+编辑行为）；多镜头 → §6（总体描述+镜号+时间戳+分镜）；声音 → §4 叠加到任意公式尾部。

**互斥硬规则**：
- `reference_*` 与 `first_frame`/`last_frame` **互斥**，同传报错 → 写提示词前必须先定死走哪套
- `file` 与 `link` **互斥**，最多其一，且必须 `enable_thinking=true`
- `last_frame` 必须搭配 `first_frame`

## 2. 提示词写作层面的五条硬约束

| # | 约束 | 对提示词的影响 |
|---|---|---|
| 1 | **`negative_prompt` 已废弃，不再支持** | 所有"不要 X"必须改写成**正向排除**（见 §4）。这是 wan3.0 最大的写作变化 |
| 2 | `prompt` ≤ **5000 字符**，中英文各算 1 字符 | 长分镜要压缩，优先砍形容词堆砌，保留动作/台词/空间 |
| 3 | `audio` 默认 **true**（有声），开关同价 | 不写声音层 → 模型自由发挥出不可控人声/BGM。不要台词写「**全片无台词**」，不要配乐写「**无背景音乐**」 |
| 4 | `ratio` 默认 **`adaptive`** 自适应 | 想锁竖屏/横屏**必须传参数**，不要靠提示词写"竖屏"，模型不吃 |
| 5 | `duration` 2–30 或 `-1`（智能时长），默认 5 | 动作密度必须匹配时长：5s 只能承载 1 个主动作；台词字数 ≈ 时长×4 字 |

`prompt` 与 `media` **至少填其一**。

## 3. 参考指代写法

公式：**提示词 = @参考对象 + 动作 + 台词**（全文见 `wan3-formulas.md` §5）

- 图片写 `@图片1`、`@图片2`…；视频写 `@视频1`、`@视频2`…；音频写 `@音频1`… —— **带 `@` 前缀，用全称"图片"不是"图"**
- 序号 = 该类型内的上传顺序，**图片 / 视频 / 音频分开计数**
- **同一个对象可以在提示词的不同位置多次 @**，用来精准控制参考意图，也是提高遵循度的推荐手段
- 音色引用**与说话动作同句**，台词后紧跟「音色参考 @音频1」（如「XX 说："……"，音色参考 @音频1」）；独立成句的"提取 @音频1 的音色特征"前置式**不生效**
- 时序参考：只想借视频的运镜/动作/特效时写「参考 @视频1 的运镜方式」
- 白膜参考：「将 3D 预览视频转化为正式成片，把预览视频中……换成……角色」
- 台词：写了 `xx说："xxx"` 模型保持台词不变；不写则自由发挥；**不要台词写「全片无台词」**
- BGM：不写模型自行发挥；**不要 BGM 写「无背景音乐」**
- 一镜到底：写「**生成单镜头**」或「**一镜到底**」（`shot_type` 参数已取消，只能靠提示词声明）

> ⚠️ **迁移警告**：旧版写法是不带 @ 的「图1 / 视频1」。
> **wan3.0 口径是带 @ 的 `@图片1`**。沿用旧写法可能降低指代命中率，改写历史 prompt 时优先替换成 @ 形式。

**声音配对**：`reference_image` / `reference_video` 子对象可挂 `reference_voice`，给该角色指定音色。多角色对话时逐个挂 —— **参数级锁定比提示词里写"音色参考 @音频1"更硬**，两者可以同时用。

## 4. 正向排除写法（negative_prompt 废弃后的唯一手段）

模型对否定词不敏感，「不要出现 X」常常反而召唤 X。统一改成**描述目标状态**：

| ❌ 否定写法 | ✅ 正向排除 |
|---|---|
| 不要出现文字/字幕 | 画面干净无叠加图形，纯实拍质感 |
| 不要变形 | 五官与肢体比例保持稳定自然，轮廓边缘清晰 |
| 镜头不要动 | 固定镜头，机位与焦距全程不变 |
| 不要有人声 | 无台词，仅保留环境音 |
| 不要多余的手 | 双手始终在画面内且可数，动作简洁 |
| 背景不要乱 | 背景为单一浅灰无缝墙面，虚化处理 |
| 不要慢动作 | 动作以真实速率进行，节奏连贯 |

## 5. 输入媒体规格

| type | 上限 | 格式/尺寸 |
|---|---|---|
| `reference_image` | ≤10 张 | JPEG/JPG/PNG（不支持透明通道）/BMP/WEBP；≤20MB；单边 [240,8000]px；长宽比 ≤8:1 |
| `first_frame` / `last_frame` | 各 1 个 | 同上；与参考模式互斥 |
| `reference_video` | ≤5 段，总 ≤15s，单段 [1,15]s | mp4/mov；<100MB；单边 [240,4096]px；长宽比 ≤8:1 |
| `reference_audio` | ≤5 段，总 ≤15s | wav/mp3；<15MB |
| `file` | 1 个 | docx/xlsx/pptx/pdf/txt/md/key/pages/numbers；≤100MB；≤50 页；需 thinking |
| `link` | 1 个 | 公开无需登录网页；国内不解析海外 URL；需 thinking |

**有视频输入时「输入总时长 + 输出 duration ≤ 30s」**，超了报 `duration exceed`。

## 6. 参数速查

| 字段 | 取值 | 默认 |
|---|---|---|
| `resolution` | `1080P` / `720P` / `480P` | `1080P` |
| `ratio` | `16:9` / `4:3` / `1:1` / `3:4` / `9:16` / `adaptive` | `adaptive` |
| `duration` | 2–30 或 `-1` | `5` |
| `audio` | true / false | `true` |
| `enable_thinking` | true / false | `false` |
| `seed` | 0–2147483647 | 随机 |
| `watermark` | true / false | `false` |

计价参考：480P 0.3 元/秒、720P 0.6 元/秒、1080P 1.2 元/秒。**10s 1080P ≈ 12 元**，批量跑 case 前先估成本（以平台当前价目为准）。

`enable_thinking=true` 的用处：文件/网页解析（必开）、联网知识增强、复杂图像理解（例如画了运动轨迹线的示意图）。写提示词时如果依赖"看懂一张示意图/读一份文档"，必须提醒开思考。

> `prompt_extend`（自动改写参数）在 wan3.0 参数表中**未列出**，能否使用**待核实**。当前策略：不依赖 `prompt_extend`，用结构化公式把提示词一次写足。

## 7. 出片确认清单

**默认只交提示词，不自动出片。** 只有用户明确说"跑一下 / 出 case / 生成看看 / 批量跑"才进入出片流程，且提交前先把 `duration / resolution / ratio / audio` 列出来给用户确认。

- **单条**：先校验请求体（形态互斥、媒体上限、时长预算）再提交，避免白耗额度
- **批量**：先出清单（Excel/JSONL：镜号 / 场景 / 角色 / 参考图 / 台词 / 提示词 / duration / ratio）给用户补齐时长与宽高比，再逐 case 提交

**出片侧已知坑**：
- 长任务易 504 `ResponseTimeout` → **单次 duration 别贪长**，长内容拆多段
- 任务长时间 PENDING 是排队，不要 cancel
- `video_url` 约 24h 过期，完成立刻下载
- 本地大文件走可访问的 URL，不要 base64（易 SSL EOFError）
